## Parent

Part of #1 — [使用跨平台 Secure Storage 保護 Classroom Connection](https://github.com/mz038197/classroom-app/issues/1)。

## What to build

讓更新版本的學生在啟動時自動將舊版明文憑證遷移至安全儲存，並在遷移或刪除失敗時得到明確且不洩密的處理結果。

遵守母議題的 [Secure Storage ADR](https://github.com/mz038197/classroom-app/blob/master/docs/adr/0001-secure-storage.md) 與 [Classroom App Context](https://github.com/mz038197/classroom-app/blob/master/CONTEXT.md)。不變更 Router 兌換、Course Catalog 或 Session Model Allowlist API 契約。延續 node:test 與 dependency injection 慣例，核心測試優先使用既有 storage seam。

## Acceptance criteria

- [ ] 啟動偵測舊版明文連線，先加密並驗證可解密，再安全替換；成功後不留可正常存取的明文舊檔、暫存備份或額外課堂身分資料。
- [ ] 加密、驗證或替換失敗時移除舊明文憑證並要求重新 Nickname Redeem；不得將舊金鑰當作 Temporary fallback 或送 Router。
- [ ] 明文刪除失敗時停止使用該憑證，畫面提供簡短手動清除指引；訊息不回顯金鑰，不宣稱一般刪除等於物理安全抹除。
- [ ] 舊版僅有 API Key 而欠缺 metadata 時不捏造 Class Label、Nickname 或其他缺失欄位，不依赖不存在的 Router API；保守呈現，之後成功兌換再補齊。
- [ ] 同一行程的重複或併發啟動／HTTP Server 初始化只進行一次必要遷移，結果冪等，不破壞已建立的連線。
- [ ] 測試覆蓋成功、加密／解密驗證／替換失敗、刪除失敗、缺 metadata 與重複初始化，從恢復狀態、磁碟結果與是否送 Router 驗證行為。
