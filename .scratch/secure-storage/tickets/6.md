## Parent

Part of #1 — [使用跨平台 Secure Storage 保護 Classroom Connection](https://github.com/mz038197/classroom-app/issues/1)。

## What to build

讓學生確實撤去本機 Classroom Connection，得到與持久化結果一致的清除回饋，並保留其他工具設定。

遵守母議題的 [Secure Storage ADR](https://github.com/mz038197/classroom-app/blob/master/docs/adr/0001-secure-storage.md) 與 [Classroom App Context](https://github.com/mz038197/classroom-app/blob/master/CONTEXT.md)。不變更 Router 兌換、Course Catalog 或 Session Model Allowlist API 契約。延續 node:test 與 dependency injection 慣例，核心測試優先使用既有 storage seam。

## Acceptance criteria

- [ ] Clear Classroom Connection 成功時清除記憶體與安全持久化的憑證及相關課堂資料，移除 Class Label、Nickname 與 Copy Key 入口，Model Switch 回到 Native。
- [ ] 清除後重啟不恢復連線；課堂模型不可用，不再以舊金鑰送 Router，但清除連線不等同停止本機代理。
- [ ] 持久化清除失敗時提供受控且不洩密的錯誤，不宣稱連線已完全清除；畫面清楚反映失敗，不讓學生誤以為重啟後一定不會恢復。
- [ ] 不刪除其他 Copilot provider、Codex／Claude 個人設定或 Workspace MCP Config；Native 設定恢復遵守既有路由慣例。
- [ ] Temporary 與 Persistent 連線皆涵蓋成功清除；以 storage fake 驗證清除失敗、複製入口、Mode、代理行為及重啟結果，客戶端設定保留的回歸測試通過。
