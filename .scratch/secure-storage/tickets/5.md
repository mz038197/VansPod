## Parent

Part of #1 — [使用跨平台 Secure Storage 保護 Classroom Connection](https://github.com/mz038197/classroom-app/issues/1)。

## What to build

讓學生換堂時，正在使用的 Classroom Connection 與下一次啟動會恢復的連線保持一致；不能完成安全提交就保留原連線。

遵守母議題的 [Secure Storage ADR](https://github.com/mz038197/classroom-app/blob/master/docs/adr/0001-secure-storage.md) 與 [Classroom App Context](https://github.com/mz038197/classroom-app/blob/master/CONTEXT.md)。不變更 Router 兌換、Course Catalog 或 Session Model Allowlist API 契約。延續 node:test 與 dependency injection 慣例，核心測試優先使用既有 storage seam。

## Acceptance criteria

- [ ] 兌換另一個 Class Session 時，完整處理舊持久化連線與新連線的提交；只有舊資料安全取代或清除成功後，才將新連線呈現為已完成。
- [ ] 舊持久化連線無法安全取代且無法清除時拒絕換堂，保留原本可用的連線、Class Label、Nickname、Mode 與相關模型／Catalog 狀態。
- [ ] 舊持久化資料已成功清除但新資料無法保存時，允許當次使用新 Temporary Classroom Connection；重新啟動不能恢復到上一堂。
- [ ] 安全替換成功後，當次畫面、Router 使用的 Key／Allowlist／Catalog 與重啟恢復的資料都屬於新 Class Session；不沿用上一堂的模型權限。
- [ ] 既有不可解密密文只在新的成功兌換完成安全替換或清除後讓位；失敗不誤報新連線已完成。
- [ ] 以 storage fake 驗證替換成功、替換與清除皆失敗、清除成功但保存失敗，以及各路徑的當次與重啟行為；必要錯誤不洩露金鑰。
