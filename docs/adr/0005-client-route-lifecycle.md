# 客戶端設定只在使用者切換課堂模式時接管

**狀態：Q1～Q6 已確認，使用者以 implement 授權實作；功能與本機／Windows 驗證已完成。** 日期：2026-10-12。

## Context

Claude Code 的 ANTHROPIC_BASE_URL 在移除本機代理網址後再次被寫回。修改前的 startNow 在啟動時直接設定 Claude CLI 與 VS Code 的代理網址，未以 Claude 的 Classroom 模式為條件。使用者要求 Codex 與 Claude 都必須等到切換課堂模式才寫入設定，切回個人模式時恢復。

本決策保留 ADR-0004 的模式跨啟動恢復行為，修正啟動時不依客戶端模式接管設定的行為；adapter 偏好與課堂連線的保存仍是不同事項。

## 已確定的要求

- 單純開啟 VansPod 不構成將 Native 客戶端改成 Classroom 的授權；課堂設定只能在使用者切到該客戶端的 Classroom 模式，或啟動時恢復其上次 Classroom 模式時寫入。
- 使用者將該客戶端切回 Native 時，恢復進入 Classroom 前的原設定；原本未設定的欄位恢復為未設定，不以刪除所有個人設定取代恢復。
- 延續現有每個客戶端獨立切換的規則，切換 Codex 不改變 Claude 的選擇，反之亦然。
- Q1 已確認：啟動沿用每個客戶端上次的模式；上次是 Classroom 就保持 Classroom，上次是 Native 就不寫入課堂設定。Native 客戶端若仍有 VansPod 課堂設定殘留，啟動時須恢復其個人設定。恢復原有 Classroom 仍須符合有效課堂連線與可用模型條件。
- 2026-10-22 補充：啟動時若重試後仍抓不到 Session Model Allowlist（不是老師沒開放模型，也不是 Classroom API Key 被拒），上次為 Classroom 的 Client Route 暫時以 Native 執行，但設定檔保留 Classroom，畫面請學生按「↻ 更新」。之後「更新」抓到模型，視為延後完成的啟動恢復，切回 Classroom；學生在這之前自己切到 Native、或該路由已紅燈／灰燈時不切回（紅燈依 ADR-0006 須學生自行切入）。
- Q2 已確認：Claude 的接管與恢復同時涵蓋終端 CLI 與 VS Code Claude 擴充；進入 Classroom 前保存原值，返回 Native 恢復原值，原本不存在的欄位才移除。
- Q4 已確認：接管期間由使用者或其他程式修改的設定必須保留；恢復只針對仍由 VansPod 接管的欄位，不整份覆蓋個人設定檔。
- Q5 已確認：成功保存原設定備份後才能接管；恢復失敗時保留備份供重試，明確顯示失敗，不宣稱已恢復。
- Q3 已確認：Native 啟動有課堂設定殘留但沒有可信個人設定備份時，恢復官方連線。移除能確認由 VansPod 寫入的代理覆寫，使用客戶端官方預設端點；保留既有官方登入資料，不猜原本第三方網址，不宣稱已還原未知原值，也不改動其他本機服務設定。
- Q6 已確認：每個客戶端僅保留一份作用中的原設定備份；重複啟動或重複選 Classroom 不新增、不用課堂設定覆蓋原備份。成功恢復後清除，失敗保留供重試；下次從 Native 進入 Classroom 時重新保存當時的個人設定。Claude CLI 與 VS Code 同屬該客戶端備份，全部成功恢復後才清除。

## 實作邊界

本文件處理每個客戶端的課堂設定接管及個人設定恢復，不改動 adapter 轉接內容或官方登入流程。既有關閉分頁與真正停止代理的區別保留；停止流程涉及已接管的設定時須遵守同一份原值恢復與失敗保留規則。模式記憶與備份是否已清除是不同狀態。

## 驗證方向

啟動時 Native 客戶端不新增課堂代理，有殘留則恢復個人設定；Classroom 客戶端可恢復上次課堂接管，混合模式不得互相污染。切換單一客戶端時僅接管其設定；切回 Native 後恢復其原網址、模型及相關選項，其他個人資料保留。涵蓋可信備份／無備份、重新啟動、其他程式修改、設定或備份寫入失敗，以及重複啟動不增加備份的情境。

## Implementation

每個客戶端使用一份固定名稱的設定備份，合併管理代理網址、模型、模型目錄及相關快取；Claude 同時包含 CLI 與 VS Code。寫入客戶端前先以暫存檔替換保存原值與預定寫入值；恢復失敗保留備份供重試，成功才清除。重複課堂設定寫入前將中途的個人修改合併回原值，避免重啟或重選模型後丟失修改。

舊版分離的 Codex 網址／模型備份遷移至新備份，再移除舊備份。遷移使用實際代理埠，只還原可辨認為 VansPod 接管的欄位。無備份時清理已知的代理與課堂模型／目錄覆寫；Claude 的模型以已知代理 gateway 目錄識別，成功寫回設定後才移除這份識別資料，以便失敗重試。VS Code 陣列中同時存在個人與課堂網址時，只清理課堂項目。

備份毀損、設定檔無法解析或存取被拒絕時不假定檔案為空，不覆蓋未知內容；介面顯示恢復失敗並允許再次選 Native 重試。設定恢復不代表官方帳號已登入或網路連通。

## Validation

2026-10-12：完整測試 259 項及型別檢查通過；設定檔專項 18 項涵蓋個人網址／模型恢復、無備份官方回復、模式隔離、修改後重開課堂、舊備份遷移、實際代理埠與寫入失敗重試。Windows EXE 驗證通過 Native 啟動不改 Codex／Claude CLI／VS Code 原檔、混合模式重啟、Classroom 恢復與既有 JSON／SSE 及憑證生命週期；真實使用者設定雜湊不變。規範與需求兩軸審查發現的重播修改保留、無備份模型清理、非預設埠遷移、失敗重試識別與重複網址保留問題均已補測修正，最終無剩餘項目。最後重複網址修正另經設定檔測試與完整測試通過後重新打包。

這些檢查驗證本機設定生命週期與打包代理格式，不代表已完成真實官方登入或模型網路連通測試。
